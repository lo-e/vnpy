## 重要坑：Git Bash 环境变量代理覆盖失效
- bash 前缀 `HTTP_PROXY=... python xxx.py` **在 Git Bash 下不生效**——父环境（WorkBuddy）的 9037 代理会覆盖传入值，而 9037 是死代理（curl 无响应），导致 requests 全挂、脚本死等代理恢复。
- **解决**：Python 进程内 `os.environ["HTTPS_PROXY"]="http://127.0.0.1:10809"` 再 exec 目标脚本（包装器模式）最可靠。10809 是唯一活代理。
- 教训：以后凡是要走 Binance 的脚本，直接用包装器注入代理，别用 bash 前缀传。

## 重要坑：os.system 子进程不继承 os.environ 修改（Windows）
- 实测：包装脚本内 `os.environ["HTTPS_PROXY"]="http://127.0.0.1:10809"` 后用 `os.system(python xxx.py)` 起子进程，**子进程读到的是进程启动时的环境块**（实测为死代理 12402）→ requests 全挂、check_proxy False、脚本死等。
- 最小复现：同进程内注入 env 后 requests 默认请求 200 通；但 os.system 子进程读到 12402 且 ProxyError。
- **解决**：必须 `subprocess.run([sys.executable, "xxx.py"], env={**os.environ, "HTTPS_PROXY": "http://127.0.0.1:10809", ...})` 显式传 env。以后所有包装脚本一律用 subprocess env，不用 os.system。
